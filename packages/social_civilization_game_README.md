# 위치 기반 소셜 문명 게임 --- 핵심 기획 README

> 최종 정리: 2026-10-16\
> 상태: 아이디어 및 기술 방향 검토 단계 (확정되지 않은 항목 포함)

## 1. 게임의 비전

**현실의 지역을 기반으로 플레이어들이 직접 도시, 경제, 직업, 정치와
문화를 만들어가는 모바일 소셜 샌드박스 게임.**

-   GPS를 통해 현실 지역과 게임 속 지역을 연결한다.
-   플레이어가 땅을 개척하고 집·상점·공공시설을 건설한다.
-   같은 지역의 주민들이 모여 도시를 발전시키고 공동 의사결정을 한다.
-   플레이어들이 제작한 의상·건축물·서비스가 거래되며 경제가 형성된다.
-   도시 사이에 외교·동맹·원정·영토 경쟁이 생길 수 있다.
-   게임의 역사는 개발자가 정한 줄거리가 아니라 플레이어의 행동으로
    만들어진다.

## 2. 가장 중요한 설계 원칙

1.  **직업은 선택지가 아니라 활동의 결과:** 옷을 디자인하면 디자이너,
    건물을 설계하면 건축가, 상점을 운영하면 상인이 된다.
2.  **플레이어가 콘텐츠 생산자:** 개발자는 제작 도구와 규칙을 제공하고,
    플레이어가 실제 콘텐츠를 만든다.
3.  **개인 소유와 공동체 권한을 구분:** 개인 영지는 보호하고,
    공공시설·지역 정책은 주민 의사결정으로 운영한다.
4.  **다양한 플레이 방식 공존:** 꾸미기·창작·거래·교류·정치·전략을 모두
    지원한다.
5.  **현실 위치는 입장과 개척에 활용:** 게임 속 아바타 위치를 다른
    플레이어에게 보여주되, 정밀한 실제 GPS 위치는 공개하지 않는다.

## 3. 플레이어 제작 콘텐츠(UGC)

### 캐릭터

-   귀여운 **카툰 스타일 3D 캐릭터**.
-   눈·코·입·얼굴형·머리·체형 등을 슬라이더로 조절하는 캐릭터
    크리에이터.
-   얼굴 형태 변형에는 **블렌드 셰이프(Morph Target)** 방식 검토.
-   캐릭터가 서로 다른 체형이어도 의상이 맞도록 공통 규격 필요.

### 의상 디자인

-   플레이어가 옷의 색상·패턴·그림 등을 직접 디자인.
-   의상실·브랜드·상점을 운영하고 디자인을 판매.
-   초기에는 **기본 의상 형태 + 사용자 제작 텍스처/패턴** 방식 권장.
-   의상 형태 자체의 자유 제작은 추후 확장.

### 건축 디자인

-   집·성·상점 등의 **외형을 플레이어가 직접 설계**.
-   초기에는 벽·바닥·창문·문·지붕 등을 조합하는 **3D 모듈형 건축** 권장.
-   건축 설계도를 저장·복제·판매하고 다른 플레이어의 건축 의뢰를 받을 수
    있음.
-   완전 자유 3D 모델링이나 복잡한 복셀 건축은 장기 확장 후보.

### 사회적 활용

-   지역에서 시청 건축 설계 공모전을 열고 주민 투표로 선정.
-   패션 축제에서 주민들이 직접 디자인한 의상을 전시·판매.
-   건축가·디자이너·상인·생산자·정치인 등 역할이 자연스럽게 형성.

## 4. 세계와 그래픽 방향

**선호 스타일: 카툰풍 아이소메트릭 2.5D.**

중요한 구분: **2.5D는 보이는 시점이고, 내부 그래픽은 실제 3D로 구현
가능하다.**

-   세계: 부드러운 색감의 카툰 스타일 3D 지형·건물.
-   카메라: 평소에는 위에서 비스듬히 보는 고정 아이소메트릭 시점.
-   캐릭터: 실제 3D 모델을 사용해 얼굴·체형을 세밀하게 변형.
-   캐릭터 편집 화면: 얼굴 확대, 회전, 슬라이더 조정.
-   건축 편집 화면: 3D 부품 배치와 외형 확인.
-   건축물 간 통일감 확보: 공통 비율, 재질·색감, 조명, 부품 규격.

## 5. 실시간 멀티플레이

-   같은 게임 지역에 접속한 캐릭터들이 **동시에 움직이는 모습**을 표시.
-   조이스틱/터치로 아바타를 이동시키는 방식 추천.
-   집 방문, 광장 모임, 채팅, 공동 건축, 시장 거래, 원정대 조직.
-   GPS는 어느 지역에 접근·입장할 수 있는지 확인하는 용도로 사용.
-   동시 접속자가 많아지면 **구역별 동기화 / 주변 캐릭터만 표시**.
-   실제 위치 추적·노출, GPS 조작, 부계정 악용에 대한 대책 필요.

## 6. 도시·사회 시스템

-   **개인 영지:** 집, 개인 작업장, 상점, 꾸미기 공간.
-   **공동 영토:** 광장, 시청, 도로, 공공시설, 공동 방어시설.
-   **정치:** 주민 투표, 공동 예산, 정책 제안, 시장 선거.
-   **경제:** 자원 생산, 제작, 상점, 거래, 창작 의뢰, 설계도 판매.
-   **외교·전략:** 도시 간 거래, 동맹, 연합, 원정, 가상 전쟁.
-   **문화·역사:** 기념비, 축제, 랜드마크, 개척 기록, 지역별 정체성.

초기 건물 후보: 집, 정원, 성, 농장, 제재소, 광산, 시장, 시청, 학교,
감시탑, 도로, 기념비.

## 7. 기술 방향: Flutter vs Unity

### 이전 검토

**Flutter + Flame**은 2D 스프라이트 기반의 카툰풍 아이소메트릭 게임,
단순 건물 배치, 2D 의상 변경, 소규모 실시간 캐릭터 이동에 적합하다.

### 요구사항 확장 후 권장

얼굴 형태를 슬라이더로 세밀하게 바꾸고, 3D 의상과 자유로운 건축 편집까지
지원하려면 **실제 3D 게임 엔진이 유리**하다.

  영역               현재 추천
  ------------------ -------------------------------------------
  핵심 게임 엔진     **Unity 또는 Godot** (미확정)
  월드 렌더링        카툰 스타일 3D + 아이소메트릭 카메라
  캐릭터 외형 편집   3D 모델 + 블렌드 셰이프
  건축 편집          모듈형 3D 부품 조립
  서버·영구 데이터   Firebase 등 검토
  실시간 이동        지역별 실시간 네트워크 서버 검토
  AI 개발 지원       Codex로 코드·씬 구성·에디터 자동화
  정교한 3D 에셋     Blender·외부 에셋·아티스트 작업 필요 가능

**중요:** Codex는 Unity 프로젝트 코드 작성, 기본 3D 메시 생성, 씬 구성과
도구 제작을 도울 수 있지만, 상용 수준의 캐릭터·의상·애니메이션까지
자동으로 완성해 준다고 보장할 수는 없다. 실제 에디터 조작 범위는 연결한
도구와 환경에 따라 달라진다.

## 8. 추천 개발 순서(MVP)

1.  **비주얼 프로토타입:** 작은 카툰풍 3D 마을, 아이소메트릭 카메라,
    캐릭터 1명 이동.
2.  **캐릭터 크리에이터:** 얼굴 슬라이더, 헤어·의상 변경, 외형 저장.
3.  **건축 편집기:** 벽·문·창문·지붕 조립, 설계도 저장 및 재배치.
4.  **실시간 공유:** 같은 지역에 2\~10명 접속, 캐릭터 이동·건물 상태
    동기화.
5.  **창작 경제:** 의상 디자인·판매, 건축 설계도 거래, 상점 운영.
6.  **지역 공동체:** 주민·투표·공동 건축·시청.
7.  **확장:** 도시 간 무역·외교·연합·원정·전쟁.

**개발 우선순위:** 먼저
`카툰 3D 세계 + 캐릭터 커스터마이징 + 건축 편집`이 기술적으로 자연스럽게
연결되는지 검증한다.

## 9. 아직 결정할 사항

-   Unity와 Godot 중 최종 엔진.
-   캐릭터 비율(귀여운 2\~3등신 / 중간 4\~5등신 / 현실형 6\~7등신).
-   건축 자유도(모듈형 / 복셀형 / 완전 자유 모델링).
-   옷 제작 자유도(패턴 편집 / 형태까지 직접 제작).
-   영토 구획·개척·주민 등록 규칙.
-   실시간 지역별 동시 접속 목표 및 서버 비용.
-   경제, 소유권, 투표, 외교·전쟁의 세부 규칙.
-   사용자 제작 콘텐츠 검수·저작권·신고 시스템.
