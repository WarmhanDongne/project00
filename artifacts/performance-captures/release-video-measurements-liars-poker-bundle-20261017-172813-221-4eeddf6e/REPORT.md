# Release 영상 동작별 시간 측정 — 2026-10-17

**로비 첫 관측 요청이 후속 요청보다 길고, 게임 시작·재시작과 폰 카드팩 소요 시간은 측정 기준이 불충분하여 철회했다. 일반 제출 10회에서는 A 화면의 다음 턴 안내까지 약 0.8초였다.**

이 보고서는 UI에 보이는 피드백·연출 기준이다. 손가락이 처음 닿은 시점부터의 계측값이나 순수 서버 응답 시간으로 읽으면 안 된다.

## 측정 범위와 기준

- 원본 MP4 9개를 읽기만 했다. 영상 ID와 원본 해시는 아래 목록 및 measurements.json에 기록했다.
- 먼저 전체 구간을 일정 간격으로 탐색한 뒤, 로비 0.25초·일반 제출 0.1초·게임 시작 0.5초 간격으로 전환 경계를 좁혔다.
- 표의 초는 영상 내부 상대 시각이다. 원본 파일명 timestamp를 무조건 녹화 시작으로 사용하지 않았다.
- 오차 구간은 마지막 미충족 표본과 첫 충족 표본의 사이로 기록했다. 이는 디코더의 실제 표시 PTS나 물리 입력 지연을 보장하는 오차 한계가 아니다.

- B 영상이 없으므로 A 화면에 다음 사람 안내가 보인 것과 B가 실제 입력할 수 있게 된 것을 구분했다.

## 게임 시작·재시작 / 폰 카드팩 등장 시간 측정 — 성능 측정 철회

**이 두 항목은 유효한 성능 측정 결과로 사용하지 않는다. 기존 대표값과 첫 시작·후속 재시작 비교를 철회한다.**

- 시작을 특정 버튼의 처리 이벤트 또는 요청 전송 이벤트로 확정하지 못했고, 자리 배치 완료·메뉴 재시작·결과 재시작이라는 서로 다른 경로를 섞었다.
- 종료는 화면 구성요소의 시각적 식별이며, 배분 완료·카드팩 도착·입력 활성화 중 어느 논리적 완료 이벤트인지 검증하지 못했다.
- 폰 값은 별도 영상의 기기 시계 정렬에 의존한다. 이 정렬과 대응만으로 요청 단위의 전체 지연을 확정할 수 없다.
- 사용자 조작 대기와 시스템 처리 구간을 모두 분리했다고 보장할 수 없다. 기존의 제외 완료 표현도 철회한다.
- 이전 영상 상대 시점과 계산값은 measurements.json의 withdrawnVisualObservations에 재검토용으로만 보존한다. 정상 지연 통계·개선 전후 비교·최적화 판단에 사용하지 않는다.
- 정확한 재측정에는 시작·재시작 경로별 요청 시작, 응답 수신, 상태 수신, 연출 완료 및 입력 활성화 이벤트가 필요하다. 같은 기기의 구간은 단조 증가 시계로 계측하고 사용자 입력 대기는 별도 구간으로 남겨야 한다.

- 3번 중단 화면, B 끊김 및 재시작 약 2회라는 사용자 관찰은 유지한다. 카드 뒷면 탭 대기와 연결 중단은 구분한다.

## 코드 대조와 다음 조사 지점

- `PhoneHandCardStack`은 제출 시 420ms 이탈 연출을 서버 응답과 병행한다. 로컬 카드가 사라진 것만으로 요청 성공을 판정하지 않는 측정 기준을 적용했다.
- `CardReceiveAnimation`은 카드팩 도착 후 사용자의 탭을 기다린다. 현재 코드의 진입·공개 기준 시간은 합계 2,200ms지만 수기 측정값 대신 넣지 않았다.
- 해당 관련 소스는 APK 기준 b921f53과 작업 HEAD 사이의 파일 차이가 없음을 확인했다. 설정된 시간과 실제 측정 시간을 별개로 취급한다.
- 후속 최적화 조사에서는 로비 후속 생성 2~3초대와 첫 요청, 시작 미완료 및 연결 오류를 우선 분리할 근거가 생겼다. 개선율이나 단일 원인은 아직 확정하지 않았다.
