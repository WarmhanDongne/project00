## 1. 결론

확인: 17건 모두 선공 폰이 마지막에 준비됐다. 전체 중앙값은 최초 15.01초, 메뉴 10.09초, 결과 11.88초다.
주요 구간: 카드 배분 연출 약 2.82초, 손패 반영 후 폰 안내 약 3.64/1.94/3.63초가 흐름을 이어간다.
개선 여지: 폰 안내의 직렬 배치와 배분 뒤 상태 전달은 검토 근거가 있다. 의도된 연출을 낭비로 판정한 것은 아니다.
미확인: 요청 변동의 서버·인증·통신별 원인, 무선 ADB의 게임 성능 영향, 실제 단축 효과는 이번 자료로 분리할 수 없다.
우선 행동: 폰 안내를 겹쳐도 되는지 결정하고, 배분 완료 통보부터 손패 반영까지의 원인을 좁힌 뒤 같은 조건으로 비교한다.

## 2. 시나리오별 전체 흐름

대상: 10/18 예비 검증 뒤 유효 본 수집 17건(최초 6·메뉴 5·결과 6). 복구본 1건과 추가 승인된 결과 1건 포함. “최초”는 자리 배치 후 시작 경로이며 앱·서버의 첫 실행 조건을 뜻하지 않는다.

단위: 초. 전체 완료는 버튼 콜백부터 태블릿·선공 폰 중 늦은 입력 준비 프레임까지다. 실제 제출은 포함하지 않는다. 대기 제외는 관측상 두 기기 모두 자동 작업 없이 사용자 탭만 기다린 구간을 한 번만 뺀 값이다. CPU 시간이나 즉시 탭했을 때의 예상 시간이 아니다.

아래는 각 경로에서 중앙값에 가장 가까운 실제 1회다. 위·아래 줄은 동시에 흐른다. 폰의 “상태 대기”에는 태블릿 진행이 포함된다. 단계별 중앙값은 서로 다른 회차에서 올 수 있으므로 합산하지 않는다.

대표 흐름은 본문 PDF의 기기별 시간선으로 표시했다. 같은 시간축에서 위·아래 줄은 병행되고, 요청 띠는 연출 위에 겹쳐 표시된다.

- 최초 시작: 버튼→태블릿 더미 3.51초; 배분 2.82초 뒤 폰 상태 반영 0.86초 → 폰 안내 3.64초 → 카드팩 등장 0.75초 → 사용자 탭 대기 0.62초 → 공개 1.47초 → 입력 준비 잔여 0.03초. 이 값은 단계별 중앙값이며 전체 시간에 합산하지 않는다.
- 메뉴 재시작: 버튼→태블릿 더미 0.63초; 배분 2.82초 뒤 폰 상태 반영 0.40초 → 폰 안내 1.94초 → 카드팩 등장 0.76초 → 사용자 탭 대기 0.59초 → 공개 1.47초 → 입력 준비 잔여 0.04초. 이 값은 단계별 중앙값이며 전체 시간에 합산하지 않는다.
- 결과 재시작: 버튼→태블릿 더미 0.64초; 배분 2.82초 뒤 폰 상태 반영 0.84초 → 폰 안내 3.63초 → 카드팩 등장 0.76초 → 사용자 탭 대기 0.24초 → 공개 1.47초 → 입력 준비 잔여 0.07초. 이 값은 단계별 중앙값이며 전체 시간에 합산하지 않는다.

품질·한계: 17건 모두 해시·순번·게임/기기 연결·실제 선택/제출 검증 통과. 전체와 대기 제외 시간의 추정 범위 폭은 최대 0.145초(기준 0.250초). Debug 기준이며 Release 속도·프레임 품질을 뜻하지 않는다. 동일 기기·2폰 참여 조건을 유지하되 앱 재실행·캐시·네트워크 조건이 완전 통제된 시나리오 비교는 아니다.
