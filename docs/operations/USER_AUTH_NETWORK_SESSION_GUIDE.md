# 로그인·네트워크·세션 기능 안내

이 문서는 사용자가 앱에서 보게 되는 흐름을 설명합니다. 구현의 상세 근거와 상태값은
[`AUTH_NETWORK_SESSION_TECHNICAL_REFERENCE.md`](AUTH_NETWORK_SESSION_TECHNICAL_REFERENCE.md)에
정리되어 있습니다.

## 한눈에 보는 동작 순서

1. 로그인한다.
2. 처음 로그인한 계정은 비밀번호·프로필 등 남은 온보딩 단계를 마친다.
3. 태블릿은 방을 만들고 방 코드를 저장한다. 휴대폰은 방 코드와 닉네임으로 참가하고
   참가 정보를 저장한다.
4. 연결 중에는 태블릿과 휴대폰이 약 10초마다 heartbeat를 보내고, RTDB의
   `onDisconnect`가 예기치 않은 연결 종료를 표시한다.
5. 잠깐 인터넷이 끊기면 앱은 현재 화면을 보존하고 재연결을 시도한다. 휴대폰은 참가
   정보를 다시 확인하고, 태블릿은 같은 방의 컨트롤러 세션을 복구한다.
6. 게임이 끝나 결과 화면을 닫으면 방은 대기 상태로 돌아가고 `selectedGame`과 이전
   게임 데이터가 정리된다.

## 로그인과 첫 설정

### 이메일 링크

이메일 주소를 입력하면 로그인 링크가 발송됩니다. 링크를 이 앱에서 열면 Firebase
Auth가 계정을 확인하고, 서버가 온보딩 상태를 준비합니다. 같은 기기에 보관된 이메일
정보는 링크 처리와 재전송 대기시간 계산에만 사용됩니다.

### Google과 Apple

Google 또는 Apple의 로그인 화면에서 인증한 뒤 그 인증 결과를 Firebase Auth 계정과
연결합니다. 서버는 제공된 이름·사진을 사용자 프로필에 동기화합니다. 필수 정보가
부족하면 프로필 설정 화면으로 이동합니다. Apple은 사용자가 이름이나 이메일 공유를
숨길 수 있으므로 추가 입력이 생길 수 있습니다.

### 온보딩 단계

- `settingPassword`: 이메일 링크 가입자가 앱용 비밀번호를 설정하는 단계
- `settingProfile`: 닉네임·프로필 등 필수 정보를 채우는 단계
- `complete`: 홈 화면을 사용할 수 있는 단계

이 단계는 Firestore의 서버 관리 문서를 기준으로 판단합니다. 휴대폰 화면 회전이나 앱
재실행이 있어도 Firebase Auth의 로그인 상태와 이 문서를 다시 읽어 알맞은 화면으로
돌아갑니다.

## 태블릿 방과 휴대폰 참가 세션

태블릿은 방 코드와 컨트롤러 세션 ID를 기기에 저장합니다. 앱이 백그라운드로 가거나
화면이 잠시 사라졌다는 이유만으로 방을 닫지 않습니다. 다시 열면 저장된 세션과 서버의
방을 대조해 같은 방을 복원합니다.

휴대폰은 로그인 사용자 ID, 방 코드, 닉네임, 캐릭터를 기기에 저장합니다. 앱을 다시
열었을 때 “참가 중인 방으로 돌아갈까요?”라고 묻고, 사용자가 동의한 뒤에만 참가자
상태를 되살리고 heartbeat를 시작합니다. “나중에”를 선택하면 이 기기의 저장 정보만
지우며, 서버에는 이미 끊긴 참가자가 잠시 남아 있을 수 있습니다.

## 연결 감지와 복구

- `heartbeat`: 앱이 살아 있고 서버에 쓸 수 있음을 주기적으로 알립니다.
- `presence`: 현재 연결 여부와 마지막 heartbeat 서버 시각입니다.
- `onDisconnect`: Firebase 연결이 실제로 끊겼다고 서버가 판정할 때
  `isConnected: false`를 기록하도록 미리 예약합니다.
- 네트워크 복구: RTDB의 `.info/connected`가 다시 연결됨을 알리면 저장된 세션을
  이용해 presence와 `onDisconnect` 예약을 다시 만듭니다.

비행기 모드나 공유기 단절 직후에는 운영체제와 Firebase의 기존 연결이 만료될 때까지
서버의 연결 종료 판정이 늦을 수 있어, 태블릿은 이미 받고 있는 참가자 `lastSeen`도
확인합니다. 마지막 heartbeat가 20초를 **초과**하면 서버에 한 번 검증을 요청하고,
서버가 최신 값도 오래됐는지 다시 확인한 뒤에만 연결 끊김으로 확정합니다.

## 게임 중 단절

참가자의 `isConnected`가 `false`로 바뀌면 태블릿 참가자 목록에 `연결 끊김`을
표시하고, 서버의 공용 중단 상태가 게임을 멈춥니다. 서버가 중단을 시작한 뒤에는 현재
턴 마감 시각을 비우고 남은 시간을 보존하며, 참가자가 돌아오면 다시 계산합니다.
따라서 단절 판정 전까지 타이머가 진행되는 현상과 판정 후에도 타이머가 진행되는 오류는
구분해야 합니다.

태블릿 연결이 끊기면 별도의 컨트롤러 presence가 게임을 일시 정지시킵니다. 태블릿은
재연결 화면을 보여 주고 같은 방을 복구합니다. 일시적인 문제라면 그대로 기다릴 수 있고,
기다릴 수 없으면 `게임과 그룹 나가기`를 선택할 수 있습니다. 대기 중인 방은 마지막 태블릿 heartbeat 뒤 3분, 게임 중인 방은 15분의
서버 보존 시간을 사용하며 정리 작업은 별도 주기로 실행됩니다.

## 게임 종료와 대기실 복귀

정상 종료 후 결과 화면을 닫으면 태블릿이 기존 서버 명령을 호출해 방을 `waiting`으로
돌리고 `selectedGame`, 게임 공개·비공개 데이터, 종료 관련 필드를 정리합니다. 결과
화면과 태블릿 강제 종료가 겹쳐 앱이 `finished` 상태에서 다시 시작된 경우에도 태블릿
홈에서 같은 정리를 시도합니다.

## 퇴장·강퇴·방 종료의 차이

- 대기실 퇴장: 휴대폰 사용자의 참가자 노드만 서버가 제거하고 기기의 참가 세션도
  지웁니다.
- 게임과 그룹 나가기: 게임별 서버 함수가 게임 명단과 방 참가자를 함께 정리한 뒤,
  기기의 참가 세션도 지웁니다. 즉 현재 제품에서는 그룹 대기실 복귀가 아니라 그룹
  퇴장입니다.
- 강퇴: 태블릿이 특정 참가자를 방에서 제거합니다. 제거된 휴대폰은 구독 결과로 이를
  감지해 로컬 세션을 정리합니다.
- 방 종료: 태블릿만 수행합니다. 방을 닫힘 상태로 만들고 컨트롤러 매핑을 해제한 뒤
  보존 시간이 지나 서버가 최종 삭제합니다.

“게임 나가기 → 그룹 대기실 복귀”는 세 게임의 서버 퇴장 처리, 방 참가자와 게임 명단의
관계, 중단·재접속 상태를 함께 바꾸는 제품 계약 변경입니다. 별도 승인 없이 현재 동작을
바꾸지 않습니다.

## 개발 오류 확인

개발 빌드에도 오류 배지·목록·원문·stack trace는 화면에 나타나지 않습니다. 개발자는
실행 터미널에서 `[dev_error]`를 검색하거나, USB 디버깅 기기에서 아래처럼 확인합니다.

```powershell
adb logcat -v time | Select-String -Pattern '\[dev_error\]|room_connection'
```

로그에는 개인정보가 아닌 `context`, `errorType`, 첫 프로젝트 frame만 남습니다.
사용자에게 필요한 네트워크 안내와 쉬운 오류 문구는 기존 화면에서 계속 제공합니다.

목록은 자동으로 사라지지 않습니다. 이미 본 항목도 회색 배지로 남는 것은 진단 기록을
보존하는 현재 동작입니다. 네이티브 플러그인의 알려진 오류처럼 사용자 메시지에서
제외한 진단도 로그에는 남을 수 있습니다.

## 자동 검사와 실제 기기 검사의 경계

자동 테스트는 상태 해석, 화면 전환, 저장·복원 의도, 서버 트랜잭션, 중단 시 타이머
정지·복구, 종료 후 대기실 정리, 작은 화면 레이아웃을 검사합니다. 그러나 다음은 실제
운영체제와 Firebase 연결이 있어야 확인할 수 있습니다.

- 이메일 앱에서 링크를 눌러 앱으로 돌아오는 과정
- Google·Apple 네이티브 로그인 화면
- 실제 비행기 모드에서 `onDisconnect`가 서버에 반영되는 시간
- 앱 강제 종료·화면 잠금·공유기 전환 뒤 세션 복구
- 실제 Galaxy S20+의 글꼴 배율·상태바를 포함한 레이아웃

빠른 확인 순서는
[`REAL_DEVICE_AUTH_NETWORK_SESSION_CHECKLIST.md`](REAL_DEVICE_AUTH_NETWORK_SESSION_CHECKLIST.md)를
따릅니다.
