# 네트워크 복구 간단 확인 지시문 — 2026-10-23

[측정용 release APK·배포 기록](ROOM_ACTION_RELEASE_20261022.md) · [속도 측정 지시문](PERFORMANCE_CAPTURE_CHECKLIST_20261022.md) · [기존 상세 복구 테스트](NETWORK_SESSION_REAL_DEVICE_TEST.md)

**현재 release에서 기존 복구 기능의 핵심이 유지되는지 짧게 확인한다.** 아래 4항목을 실행한다. 전체 게임·모든 장애 상황의 완전한 검증을 대신하지 않으며, 문서 작성 시점의 결과는 모두 미실행이다.

## 준비

- 태블릿 1대와 휴대폰 A·B 2대에 같은 측정용 `1.0.0+6` release APK를 사용한다. 로그인·게임 다운로드는 먼저 마친다. 라이어스포커를 사용하며 서로 다른 테스트 계정으로 참가한다. 기기가 태블릿+휴대폰 1대뿐이면 1번 로비만 확인하고 게임 항목은 미실행으로 둔다.
- **속도 측정을 먼저 끝내고 별도 영상으로 진행한다.** 의도적 단절을 정상 속도 표본에 섞지 않는다. 태블릿·휴대폰 A를 녹화하고 가능하면 B도 녹화한다. 사용자는 동작별 시간을 수기로 적지 않는다.
- 인터넷은 한 기기씩 끊는다. 휴대폰은 모바일 데이터도 꺼서 Wi-Fi가 끊겼을 때 이동통신으로 우회하지 않게 한다. 비행기 모드를 쓰면 Wi-Fi까지 꺼졌는지 확인한다. 원래 네트워크 설정을 기억해 두고 테스트 뒤 복원한다.
- 설정/빠른 설정에서 전환한 뒤 즉시 앱으로 돌아온다. 기본 항목에서는 앱 종료·잠금·그룹 나가기·참가자 제외·새 게임 시작을 섞지 않는다. 인터넷을 켤 때는 원래 Wi-Fi에 실제 연결됐는지 확인한다.
- 방 코드·자리·본인 손패를 확인해 두되 수기 입력은 필요 없다. 공유 영상에서는 계정·방 코드·손패를 가린다. 손패 보존 여부는 본인이 직접 비교해도 된다.

## 1. 로비에서 휴대폰 복구 — 1회

1. 새 그룹을 만들고 A·B가 참가한다. **A만 인터넷을 약10초 끊었다가** 원래 Wi-Fi로 복구한다.
2. 앱 재실행이나 수동 재참가 없이 같은 그룹으로 돌아오는지 본다. 태블릿에 A가 중복 표시되거나 B가 사라지면 안 된다. 로비 연결 표시의 즉시 발생 여부만으로 성공/실패를 판단하지 않는다.
3. 휴대폰2대가 준비됐다면 같은 그룹에서 라이어스포커를 정상 시작하고 A·B가 자기 손패를 받은 뒤 합법적인 행동을 한 번씩 한다. 여기까지 확인해야 캐시 화면만 남아 있는 상태와 실제 연결 복구를 구분할 수 있다. 휴대폰1대뿐이면 로비 화면 유지까지만 관찰하고 이 게임 시작/행동과 나머지 게임 항목은 미실행으로 기록한다.

## 2. 게임 중 휴대폰 복구 — 같은 게임에서 2회

1. **A의 일반 턴이 시작된 직후**, 아직 충분한 시간이 있을 때 A만 인터넷을 끈다. 마지막 카드·LIAR/FOLD·벌칙·결과 연출 단계는 피하고 다른 기기도 조작하지 않는다.
2. 태블릿에서 실제 게임 중단 안내가 나타나면 그때부터 약5초 기다렸다가 A를 원래 Wi-Fi로 복구한다. A의 로컬 연결 안내와 태블릿의 게임 중단 시점을 구분한다. 보호 중에는 진행 조작이 막혀야 한다. 가능해 보이는 경우에만 합법적인 진행 버튼을 한 번 확인하고 연타하지 않는다.
3. 모든 기기의 준비가 끝나고 보호가 풀리면 A가 합법적인 카드 제출을 **한 번** 한다. 같은 방·게임·자리·손패가 이어지고 태블릿과 B에도 행동이 한 번만 반영돼야 한다. 다음 차례의 휴대폰에서도 정상 행동을 한 번 한다.
4. **새 게임을 만들지 않고 A의 다음 일반 턴에 1~3을 한 번 더 반복한다.** 두 번째 복구에서도 참가자 유실·중복·로비 강제 이동이 없어야 한다. 도중 게임이 끝나면 두 번째 반복은 미실행으로 기록하고 같은 게임 2회 통과로 처리하지 않는다.

타이머는 서버 중단이 확인된 뒤 기다린5초 때문에 계속 소모되거나 복구 때마다 새 턴 시간으로 초기화되면 안 된다. 휴대폰의 연결 안내 이전/이후 숫자만으로 정확한 서버 중단 시각을 추정하지 않는다. 영상에서 서버 중단 화면·복구 직후·실제 행동 시점의 게임 타이머를 대조하고, 복구 대기 카운트와 게임 턴 타이머를 구분한다. 숫자가 보이지 않거나 경계가 불분명하면 타이머 보존은 `확인 불가`로 둔다.

## 3. 게임 중 태블릿 복구 — 1회

1. A·B의 인터넷은 유지하고 **태블릿만 인터넷을 끈다.** 일반 턴 초반에 시작하고 휴대폰에서도 진행 조작을 멈춘다.
2. 휴대폰에 태블릿 연결/게임 중단 안내가 나타나면 약5초 후 태블릿을 원래 Wi-Fi로 복구한다. 중단 보호 중에는 휴대폰의 게임 진행이 막혀야 한다. 참가자 제외·종료는 선택하지 않는다.
3. 같은 그룹·게임·손패·차례로 복구되고 모든 기기의 준비가 끝나면, 현재 차례의 휴대폰이 합법적인 행동을 한 번 한다. 태블릿과 다른 휴대폰에 한 번만 반영되고 다음 차례도 진행되는지 본다. 태블릿 안내만 사라지고 휴대폰이 계속 보호 상태면 미완료다.

## 4. 복구 뒤 정상 종료·새 그룹 — 1회

1. 인터넷을 모두 복원한 상태에서 태블릿의 정상 종료 UI로 게임을 끝내고 그룹 대기실로 돌아온다.
2. A·B도 검정 화면·이전 게임 화면 없이 같은 그룹으로 돌아오는지 본다.
3. 태블릿에서 초기화하고 휴대폰에도 종료가 반영되는지 확인한다. **같은 계정으로 새 그룹을 만들고 A가 참가**해 양쪽 상태가 맞는지 확인한다. 이 동작들은 속도 개선율 표본에 합치지 않는다. 끝나면 정상 초기화로 테스트 그룹을 정리한다.

## 멈춤·오류가 있으면

- 실제 인터넷을 껐는데 약60초 동안 상대 기기에 중단이 전혀 보이지 않으면 중단 안내 미확인으로 기록하고 네트워크를 복원한다. 그 표본은 중단 보호 통과로 처리하지 않는다.
- 인터넷 복원 후 약60초까지 실제 조작을 할 수 없다면 화면을 남긴다. `다시 시도`가 제공되면 **한 번만** 눌러 결과를 확인한다. 자동 복구 실패와 수동 재시도 성공은 분리해 기록한다. 이60초는 간단 시험의 관찰 구간이며 기존30초 복구 묶음 예산이나 속도 합격선을 바꾸는 값이 아니다.
- 실패한 상태에서 반복 단절을 이어 가지 않는다. 네트워크를 원래대로 돌리고 영상에 현재 문구·직전 조작을 남긴다. 결과 미확정 요청은 연타하지 않고 앱 삭제·데이터 초기화로 복구하지 않는다.
- Wi-Fi 우회·일반 턴 시간초과·정상 게임 종료가 섞였으면 실패 원인을 단정하지 않고 해당 조건을 구분한다. 기기 간 영상 정렬이 어려우면 정확한 복구 시간 대신 기능 결과만 판정한다.

## 시간이 있으면 추가 확인 (선택)

| 항목 | 조작 | 확인 |
| --- | --- | --- |
| A 앱 재실행 | 게임 중 A 앱만 강제 종료하고 태블릿 중단을 확인한 뒤 다시 실행. 복구 선택 화면이 나오면 `게임 다시 참여`를 선택 | 저장된 참가 정보로 같은 게임·손패·자리 복원, 참가자 중복 없음, 실제 행동 성공 |
| 태블릿 앱 재실행 | 게임 중 태블릿 앱만 강제 종료하고 휴대폰 중단을 확인한 뒤 다시 실행. 새 그룹 생성은 누르지 않음 | 기존 그룹·게임 복원, 휴대폰 준비 완료 후 정상 행동 성공 |

강제 종료는 Android 설정의 앱 강제 종료이며 홈 버튼·화면 잠금과 다르다. 두 선택 항목은 한 번에 하나씩, 직전 항목 복구가 끝난 뒤 실행한다. 이 항목을 생략하면 앱 재실행 복구까지 통과했다고 보고하지 않는다. 이 간단 시험은 오프라인 퇴장·제외·장시간 만료·동시 단절·모든 게임 검증을 포함하지 않는다.

## 기록은 AI가 정리

| 항목 | 판정 | 영상에서 확인할 내용 |
| --- | --- | --- |
| 로비 A 복구 | 미실행 | 같은 그룹·명단, 이후 정상 게임 시작/행동 |
| 게임 A 첫 복구 | 미실행 | 중단·보호·손패/차례/시간·행동 한 번 반영 |
| 같은 게임 A 두 번째 복구 | 미실행 | 반복 후에도 같은 게임 유지·행동 성공 |
| 태블릿 복구 | 미실행 | 전 기기 보호 해제·상태 유지·다음 행동 |
| 종료·초기화·재생성 | 미실행 | 양쪽 종료·동일 계정 새 그룹 참가 |
| A/태블릿 앱 재실행 (선택) | 미실행 | 각 항목을 따로 판정 |

AI는 원본 영상에서 기기 역할·APK·조작·복구 경계와 오류를 정리한다. 판정은 `통과/실패/확인 불가/미실행`으로 구분하며, 빈칸·안내 소멸·과거 버전의 통과만으로 현재 버전 통과를 인정하지 않는다. 모든 기본 항목이 통과해도 **이번 기기·APK·라이어스포커의 핵심 복구 확인** 범위로만 보고한다.

이 문서 작성으로 기기 조작·영상/로그 수집·운영 조회는 시작되지 않는다. 코드 변경·새 배포·새 APK 생성도 수행하지 않았다.
