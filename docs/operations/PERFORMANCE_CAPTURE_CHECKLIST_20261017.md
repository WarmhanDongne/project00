## 1. 준비

- 테스트용 그룹을 사용한다. 로그인·권한 팝업 처리는 측정 시작 전에 끝낸다.
- 모든 참여 기기에 같은 기준 APK를 사용한다. 기기마다 역할·모델·Android 버전을 적는다.
- 날짜/시간은 자동 설정으로 맞춘다. 시각 메모를 직접 작성할 필요는 없다.
- 같은 Wi-Fi를 유지한다. 다른 네트워크를 사용할 경우 종류를 기록하고 묶음 중에는 바꾸지 않는다.
- 실제 기기 로그를 사용할 때는 테스트 시작 전에 타임스탬프를 포함한 수집을 준비한다.
  기기 로그는 버퍼가 제한되어 있으므로 연속 수집이 좋으며, 사후 수집이면 종료 직후 확보한다.
  이 문서 작성만으로 수집이 시작되지는 않는다. 준비/수집/시각 대응은 AI가 기록한다.
- 화면 녹화를 시작한다. 제공되는 경우 터치 표시도 켜서 누른 시점을 남긴다.
  원본 영상의 촬영 시각 metadata를 보존한다. 시각 대조가 필요하면 수집 과정에서 확인한다.
- 로비의 각 동작 사이에는 약 10초를 둔다.
  게임 안에서는 정상 턴 제한에 맞춰 진행하며 별도의 10초 대기를 넣지 않는다.
- 최초 실행과 연속 실행을 구분한다. “첫 요청”을 서버 cold start로 단정하지 않는다.
- 라이어스 게임은 태블릿 controller 외에 참가 휴대폰 최소 2대가 필요하다.
  태블릿 1대·휴대폰 1대이면 먼저 로비 측정만 진행한다.

## 3. 게임 시작 묶음 — 게임별 3회

1. 최소 참가 인원을 갖추고 동일한 게임·인원·설정을 유지한다.
2. 게임 선택부터 촬영하되 “설정/자리 배치 최종 완료 버튼”을 누른 시점을 시작점으로 표시한다.
3. 태블릿에서 분배/게임 화면이 나타나는 시점과 휴대폰에서 첫 행동이 가능한 시점을 각각 남긴다.
4. 첫 번째와 후속 시작을 구분한다. 다시 시작은 정상 종료/재시작 UI를 사용한다.
5. 다음 카드 행동 측정과 함께 진행하고, 준비 대기·오류가 나타나면 화면을 녹화에 남긴다.

## 4. 카드 제출 / 다음 턴 — 게임별 일반 행동 합계 10회 목표

- 우선 라이어스를 측정하고 가능하면 파이널콜도 같은 방식으로 별도 기록한다.
- 라이어스는 낼 카드를 먼저 선택한 뒤 제출한다. 카드 고르는 사람의 생각 시간은 제외한다.
- 제출 입력 → 자기 화면의 제출 처리 → 태블릿 반영 → 다음 사람의 턴 표시/조작 가능을 남긴다.
- 실제 버튼 활성화가 영상에서 불분명하면 “활성화 확인 못함”으로 적는다.
  다음 사람이 오래 고민한 뒤 누른 시각을 입력 가능 시각으로 사용하지 않는다.
- 파이널콜은 뽑기·교체·버리기를 구분하고, 실행한 행동과 다음 턴 반영을 기록한다.
- 한 판이 끝나면 정상 다음 판에서 이어서 표본을 모은다. 10회를 채우려고 게임 규칙을 바꾸지 않는다.
- LIAR/FOLD, 벌칙, 마지막 카드 도전, 결과 연출·제한시간 만료는 일반 턴과 구분해 메모한다.
