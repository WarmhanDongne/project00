# 대기 단축 변경 — 실기기 결과 평가

2026-10-19 본 수집 · 기능 기준 `ea08181` · Debug protocol4

## 결론

- 최초 시작 조회의 병행은 5건 모두 작동했다. 조회 0.158~0.318초가 남은 연출 안에서 끝났고, 전환 시 조회 잔여 대기는 0초였다. **조회가 화면 전환을 직렬로 막는 경로를 줄였다는 근거**다.
- 초기화 5건 모두 서버 종료 확인·옛 접속 취소·세 기기 정리와 새 방 유지가 확인됐다. 다만 취소는 4.5~21.5ms로 짧아 이번 조건에서 큰 체감 단축 효과는 입증되지 않았다.
- 원본 자동 판정 통과는 19/20건이다. 결과 재시작 1건은 첫 제출 뒤 다음 라운드 이벤트가 중복 집계됐다. 원본은 무효로 보존하고 첫 시작 구간의 별도 복원 결과만 부록에 둔다. 선택·첫 제출 연결은 15/15건 확인했다.
- R2 영상은 초기화 뒤 새 방·실제 게임 진행·로비 복귀를, S4는 연결 오류 안내 뒤 게임 진행 재개를 보여준다. 정확한 단절 경합·폰 화면·완전한 복구 계약까지 통과한 증거는 아니다.
- 기능 개선 커밋만 통합하는 방향은 타당하다. 최종 통합 검증 및 계측 없는 앱의 짧은 실기기 확인이 남았다. G1은 생략, V1은 보류이며 전체 게임·과거 APK 호환 통과를 선언하지 않는다.

## 변경별 평가

| 변경 | 관측·코드 근거 | 판단 |
| --- | --- | --- |
| 최초 시작 조회 병행 | 조회 0.243 (0.158~0.318)초가 연출과 완전히 겹쳤다. 잔여 조회 대기 0초(5/5), 전환 대기 표식→route 교체 호출 직전 표식은 0.321~0.344ms(실제 렌더 완료 시간이 아님). 시작 성공 뒤 소유 시도·계정·방·게임 문맥을 확인하고 결과를 소비한다. | 의도한 직렬 대기 제거 확인. 개선 전과 같은 조건의 대조군이 없어 전체 체감 절감 초·비율은 미확정. |
| 초기화 보조 취소 분리 | 취소 0.005 (0.004~0.022)초, close 요청 0.775 (0.386~3.120)초. 둘은 병행했고 옛 방·접속과 새 방·접속이 구분됐다. 새 방의 모든 기기 참가 완료 뒤 보장 관찰 시간 42.866~66.333초. | 정상 경로 안전성 근거 확보. 이번 취소 비용은 작고, 큰 전체 단축 근거는 부족하다. 느린 close의 서버/DB/망 원인은 이 기록만으로 분해할 수 없다. |

최초 시작 첫 사례는 20.564초, 나머지는 14.709~14.979초였다. 느린 사례의 시작/배분 완료/선공 준비 요청은 각각 2.787/3.292/3.033초로, 같은 최초 시작 나머지의 0.636~0.933/0.430~1.280/0.389~0.498초보다 길었다. **앱 요청 경계에서 느렸다는 사실**이며 서버 콜드 스타트나 DB가 원인이라는 결론은 아니다. 병행된 요청·연출 시간을 합산해 차이의 원인을 산출하지 않는다.

배분 연출은 약 2.82초, 폰 공개 연출은 약 1.47초로 유지됐다. 폰 안내와 카드팩 순서는 의도된 동작이며 이번 수정 대상이 아니다. 15건 모두 태블릿보다 선공 폰 입력 준비가 늦었다. 실제 제출 조작→결과는 별도 지표이고 퇴장 연출과 요청이 병행하므로 서버 시간으로 읽지 않는다.

## 영상·실패와 채택 경계

R2: 0초에는 기존 두 참가자 로비, 10~60초에는 옛 방 코드·명단이 정리된 로비, 70초에는 새 방, 80초에는 두 참가자, 90초에는 자리 배치, 110~190초에는 제출·턴·라운드 진행, 195~200초 결과 화면, 204.758초 로비 복귀가 보인다. 초기화 완료와 인터넷 차단의 선후를 이번 표본만으로 확정하지 않아 **단절 경합 재현은 미확정**이다.
S4: 녹화 시작부터 배경·로딩 상태이며 버튼 조작 전은 없다. 30~50초 연결 끊김/재시도 안내 뒤 55초 배분, 60초 게임 테이블, 65~80초 제출·판정, 86.904초 다음 라운드가 보인다. 이 영상 끝에는 게임 종료·로비 복귀가 없어 그 항목은 미관측이다. 두 영상은 5초 간격 및 R2 초반 1초 간격 표본의 시각 검토이며 전 프레임·폰 입력 계측이 아니다.
별도 `165904`는 사용자 보고상 네트워크 오류다. 저장된 수집기 진단은 태블릿 로컬 HTTP 연결 상태 오류 및 종료 회수 실패이므로 제품 서버 장애로 확정하지 않는다. 성공 표본에 넣지 않고 보존한다.

기존 10/18 Debug·Release·서버 자료는 측정 조건과 요청 연결이 달라 참고 자료로 유지했다. 이전 중앙값에서 이번 값을 빼 절감량을 주장하지 않는다. 이번 자료로 정상 LP 기능과 두 병행 경로의 작동을 평가할 수 있으며, 드문 취소 지연·응답 유실은 기존 자동 회귀 근거로 구분한다. 새 운영 조회·배포·추가 제품 수정은 수행하지 않았다.
