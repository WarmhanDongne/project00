# Debug 선택·첫 제출 검증 보완 계획

2026-10-19 · codex/wait-reduction · 기능 기준 ea08181 · 임시 계측 별도 변경 유지.

## 계획

1. 탭/드래그로 실제 선택 집합이 바뀐 뒤 선택 사건을 기록한다. 거절된 탭/선택 제한은 성공 사건이 아니다.
   선택 해제·내부 정리도 상태 변경으로 구분한다. 카드 내용·index·ID는 저장하지 않는다.
2. 캡처 안에서만 유효한 선택 변경 번호와 제출 번호를 발급한다. 제출 시작/결과는 같은 번호와 선택 버전을 보존한다.
3. 선공 폰의 **해당 게임 첫 제출**만 검증한다. 직전 실제 선택(탭/드래그, 양수 개수)과 그 제출의 성공 결과가
   같은 번호·순서로 연결되어야 통과한다. 늦은 선택/다른 제출/다음 차례의 성공으로 결손을 채우지 않는다.
   선택이 입력 준비 전에 이뤄졌어도 상태가 유지되면 기록 근거로 남기되, 제출은 입력 준비 이후여야 한다.
4. 진행 표시는 COLLECTING/최종 판정 전으로 바꾼다. 시간 품질·수집 종료·선택 검증은 최종 summary에서 구분한다.
5. 앱/수집기/빌드 manifest를 protocol4로 함께 올려 이전 APK와의 혼합을 거절한다. 새 APK는 빌드 후 별도 폴더 보존.
6. 기존 00:24:40 수집·기존 계측 수정·두 기능 개선은 보존한다. 게임 규칙/선택·제출 로직/연출/요청 조건/서버 변경 없음.

## 실행 전 계획 검토

- 기존 _toggleSelection은 선택 제한 검사 전 진입만 기록하고 _startDragging 자동 선택은 미계측이다.
  실제 집합 변경을 비교하고 기존 상태 변경/콜백 뒤 기록하는 방식으로 누락·과대 집계를 함께 막는다.
- 실제 제출 중 420ms 퇴장 연출과 요청은 병행된다. 계측 번호는 await 전 캡처하고 결과만 같은 번호로 연결하며
  새 await·추가 요청·시각 보정은 넣지 않는다. UI 생명주기/캡처 epoch가 바뀌면 이전 결과를 새 시험에 기록하지 않는다.
- 기존 판정은 any(selection)/any(submit)/any(success)라 서로 다른 차례를 섞는다. 첫 제출 번호를 고정해 검사한다.
- 프로토콜 변경은 임시 Debug 데이터만 대상으로 한다. 공개 API/게임 상태/영속 데이터의 계약 변경은 아니다.
- 자동 회귀: 탭·드래그·최대 선택 제한·선택 해제·비활성·실패/재시도·늦은 다른 제출·중복/연결 누락·이전 APK 거절.
  실제 00:24:40 사건 순서의 잘못된 통과도 회귀로 고정한다.
- 판정: 이 범위로 실행 가능. 관련 테스트/분석/format 후 새 APK를 만든다. 새 FULL은 Skill에 따라 별도 승인 대상이다.

## 산출물과 확인

계측·수집기 수정, 자동 회귀, 새 APK/build-manifest/build.log, 세 기기 설치용 PowerShell, 실행 근거를 남긴다.
실기기 설치는 사용자가 진행하며 기존 앱 데이터를 삭제하지 않는다. 예비 검증은 최초 시작 1회부터 재확인한다.
검증/성능/실기기 완료 또는 임시 계측 커밋 완료로 앞서 선언하지 않는다.


## 구현 및 확인 기록

- protocol4: 실제 선택 집합 변경 뒤 `card_selection_changed`(tap/drag/state, 개수/불투명 번호)만 저장한다.
  기존 콜백의 동기 재진입이 제출을 시작할 수 있으므로 **선택 상태 변경 뒤·알림 콜백 전** 기록한다.
  게임 선택/제출 로직과 콜백 순서는 그대로다. 제출 시작 전에 번호/선택 버전을 고정하고 결과에서도 재사용한다.
- 선공·게임의 첫 submit_handler를 고정한다. 최신 실제 양수 선택 버전·개수·순서와 같은 제출/선택 번호의 결과를 검사한다.
  실패·연결 누락·중복·이른 제출은 나중 차례로 보충하지 않는다. 시간 지표와 입력 검증 상태는 별도다.
- 진행 안내는 COLLECTING/최종 판정 전으로 고정한다. 최종 stop/drain과 시계 검사를 통과해야 pilot 통과다.
- Python 34건 및 Flutter 관련 23건 PASS/exit0. 세로·가로 탭/직접 드래그, 제한/비활성/선택 해제,
  실패 결과·수집 재시작 뒤 늦은 결과·첫 제출 연결/중복/다음 차례 혼입 방지를 검사했다.
- 이번 수정에서 session/auth/서버 코드·게임 규칙·의도된 연출·기존 두 개선은 수정하지 않았다.
  최종 관련 package/분석/빌드 및 보존 결과는 ignored `build/device-test/selection-fix-20261019-d4cc5f88/`를 따른다.
- 기존 사용자 수집/계측 수정과 원본은 보존한다. FULL은 새 명시 승인 전 미실행이며 commit/push/merge/운영·자동 설치는 하지 않는다.
